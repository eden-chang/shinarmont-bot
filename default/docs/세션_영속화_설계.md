# 세션 영속화 설계 — 봇을 껐다 켜도 대화가 끊기지 않게

> 배경: 자동봇 업데이트를 위해 **운영 중 봇을 껐다 켠다**. 그때 진행 중인
> `[대화]`·`[의무실 방문]` 타래가 끊기면 안 된다. 작성 2026-07-16.

---

## 1. 무엇을 영속화했나

| 상태 | 파일 | 없으면 생기는 일 |
|------|------|------------------|
| 답글-스레드 라우팅(`utils/reply_threads`) | `state/{슬롯}/reply_threads.json` | 러너가 봇 답글에 이어 써도 **어느 타래인지 몰라 무시**된다 |
| 의무실 진료 세션(`infirmary_command`) | `state/{슬롯}/doctor_sessions.json` | 진료 대화 이력·턴 수가 사라져 **대화가 끊긴다** |
| 비밀 대화 세션(`talk_command`) | `state/{슬롯}/talk_sessions.json` | 멘션 캡 카운트가 0으로 돌아가 **캡을 우회**할 수 있다 |
| 블랙잭 게임(`blackjack_command`) | `state/{슬롯}/blackjack_sessions.json` | 베팅을 이미 차감했는데 판이 사라져 **베팅액이 유실**된다 |
| 의사 재방문 이력 | `state/{슬롯}/game_state.json` | 러셀이 매번 초진처럼 군다 |

조사의 **현재 위치**는 이미 `로그` 시트에서 복원하므로 별도 파일이 없다.

크랩스·슬롯은 **영속화할 상태가 없다** — 한 번의 호출 안에서 시뮬레이션을 끝내고
결과만 낸다(턴을 넘기지 않는다). 블랙잭만 여러 턴에 걸친 판을 들고 있다.

## 2. 설계 (`utils/json_store.py`)

- **변경 시마다 저장**. 언제 죽을지 모르므로 주기 저장은 의미가 없다.
  대화 한 턴에 수 KB 파일 하나 — 마스토돈 왕복보다 훨씬 싸다.
- **원자적 쓰기**(임시파일 + `os.replace`). 쓰는 도중 죽어도 원본이 남는다.
- **깨진 파일이면 빈 상태로 시작**. 세션 유실이 봇 기동 실패보다 낫다.
- `max_entries` LRU로 무한 증식 방지(답글 매핑 5000, 진료 세션 200).

### 왜 슬롯별 파일인가 (중요)
5개 슬롯은 **별도 프로세스**인데 각자 파일 전체를 인메모리로 들고 통째로 덮어쓴다.
같은 파일을 공유하면 **한 슬롯의 저장이 다른 슬롯의 기록을 지운다**(마지막 쓰기가 이김).
세션은 슬롯 전용이라(진료 세션은 @DOCTOR에만 존재) 파일을 나누면 조율 없이 문제가 사라진다.

> `game_state`도 2026-07-16에 같은 원칙으로 옮겼다 → §4.

### 호출측 직접 수정 주의
매니저가 돌려준 세션 객체를 호출측이 직접 고치는 자리가 있다
(`session['end_at'] = ...`, `session.total += 1`). 그런 수정은 매니저가 알 수 없으므로
**`touch(key)`를 불러 저장**시켜야 한다. 빠뜨리면 재시작 시 그 변경만 사라진다.

### 함정: 빈 저장소는 falsy
`JsonStore`는 `__len__`이 있어 **빈 저장소가 falsy**다.
`self._store = store or JsonStore(default)` 로 쓰면 주입한 빈 저장소가 조용히 무시되고
기본 파일이 쓰인다. **실제로 이 버그를 겪었다**(테스트가 서로를 오염시켰다).
→ 반드시 `store if store is not None else ...`. 회귀 테스트 있음.

### 테스트
테스트는 **임시 파일을 주입**해야 한다. 안 그러면 프로젝트 `state/`를 오염시키고
테스트끼리 세션이 새어 든다. `tests/test_json_store.py`의 `RestartSurvivalTest`가
'재시작'(같은 경로로 매니저 재생성)을 시뮬레이션해 복원을 검증한다.

## 2-1. 블랙잭 — 지급 도중 죽으면 (영속화가 새로 여는 위험)

베팅은 **딜 시점에 차감**된다. 그래서 판을 영속화해야 재시작이 베팅액을 삼키지 않는다.
그런데 판이 살아남게 만드는 순간 **새 위험**이 생긴다 — 배당을 시트에 쓰고 나서
세션을 지우기 직전에 죽으면, 살아남은 판을 [스탠드]로 재정산해 **배당을 두 번** 받는다.
(예전엔 재시작이 세션을 지워 버려서 불가능했던 일이다)

`소지금` 갱신은 read-modify-write라 멱등하지 않고, 도박용 재화 원장도 없다.
→ 지급했는지 **알아낼 방법이 없다**. 그래서 지급 직전에 `payout_attempted` 표식을
파일에 남기고, 복원 시 이 표식이 붙은 판은 **되살리지 않고 ERROR로 남긴다**.

| 선택 | 결과 |
|------|------|
| 다시 지급 | 재화가 **조용히 복제**된다. 아무도 눈치채지 못하고 되돌릴 수도 없다 |
| 지급 안 함 | 이용자가 **즉시 알아채고** GM이 `[소지금 관리]`로 보정한다 |

**보이는 손실이 조용한 복제보다 낫다** — 그래서 후자를 택했다.
`_pay`가 '쓰지 않았다'고 확언하면(batch_update 실패) 표식을 지운다.
그래야 그 판은 재시작 후에도 재시도로 살릴 수 있다.

## 3. 재시작 시 실제 동작

1. 러너: `[의무실 방문]` → 러셀 응답. 봇이 답글 status_id를 `reply_threads`에 기록(파일).
2. **운영진이 봇을 껐다 켬**(업데이트).
3. 기동 시 `state/{슬롯}/*.json`에서 세션·라우팅 복원(로그: "진료 세션 n건 복원").
4. 러너가 그 답글에 대괄호 없이 이어 씀 → `resolve(reply_to_id)`가 세션을 찾아 **그대로 이어감**.

처치 중복 방지(`finalized`)도 파일에 즉시 반영되므로,
**재시작을 사이에 두고 처치가 두 번 적용되지 않는다**(테스트 있음).

## 4. ✅ 해결됨 — `state/game_state.json` 크로스 슬롯 결함 (2026-07-16 조치)

`game_state`는 **슬롯별 분리 없이 한 파일을 공유**했고, 리셋을 스케줄러에 의존했다.
둘 다 PoC로 재현한 뒤 고쳤다.

| # | 있었던 증상 | 결과였던 것 |
|---|------|------|
| CRIT-3 | @DOCTOR가 저장하면 @STORY가 쓴 `오늘대화여부`가 파일에서 사라졌다 | **@STORY 재시작 시 [대화] 일일 제한이 풀림** |
| CRIT-4 | 00:00 리셋이 BOT1 프로세스의 싱글톤만 리셋했다 | @STORY·@DOCTOR는 자기 메모리 값을 그대로 들고 있어 **이벤트 내내 [대화]·[고발]·[의무실]이 1회만 가능** |

CRIT-4 PoC — 수정 전후 같은 시나리오:
```
1일차 [대화] 사용 → 오늘대화여부 = 1
자정 넘김 (스케줄러 리셋은 @STORY에 닿지 않는 상황 그대로)
2일차 [대화] 재시도 →  수정 전: 거부 ❌   /   수정 후: 허용 ✅
```

### 조치 내용 (2026-07-16)
- `오늘*` 키를 `{'v': 값, 'd': 'YYYY-MM-DD'}`로 저장 → 읽을 때 날짜가 오늘이 아니면 없는 것으로.
  **스케줄러 의존 소멸** → CRIT-4 해소(PoC 재실행: 자정 넘김 → 재사용 허용).
- 파일을 슬롯별로 분리(`state/{슬롯}/game_state.json`) → CRIT-3 해소(경로가 달라 덮어쓸 수 없음).
- `어제대화상대`는 `오늘대화상대`의 날짜에서 **파생** → 이월 잡 불필요.
- `reset_daily`/`carry_talk_partner`는 **no-op으로 폐기**(스케줄러 호출 호환 유지).
  0시 잡은 `purge_stale()`로 지난 기록만 정리한다(용량 관리, 판정과 무관).
- 구버전 파일(스탬프 없는 raw 값)은 **만료로 취급**한다 —
  한 번 더 풀리는 쪽이 영원히 잠기는 쪽보다 안전하다.
- 호출측(`talk`·`accuse`·`infirmary`)은 **바꾸지 않았다** — get/set/check_and_set 계약이 그대로다.

### 왜 '리셋 잡'이 아니라 '날짜 스탬프'인가
리셋 잡은 **모든 프로세스에 닿아야** 맞는데, 싱글톤은 프로세스마다 따로 있다.
잡을 5슬롯에 브로드캐스트하는 대신 **판정 자체를 시간에서 끌어내면** 조율이 필요 없다 —
누가 언제 재시작하든, 스케줄러가 죽어 있든 결과가 같다.
조사 일일 제한이 이미 이 방식(로그의 일시로 판정)이라 정확했다. 같은 교훈을 옮긴 것이다.

> 남은 인메모리: 없다. 크랩스·슬롯은 단발성이라 들고 있을 상태가 없다(§1).
