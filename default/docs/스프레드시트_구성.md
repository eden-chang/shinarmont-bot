### `관리` 워크시트 컬럼 (공유)
| 컬럼 | 세팅 | 비고 |
|------|------|------|
| 이름, 아이디 | 명단에서 자동 | |
| `소지금` | 🟦 봇 | 달러 |
| `소지품` | 🟦 봇 | 인벤토리 문자열 |
| `건강` `이성` | 🟩 초기 100 / 🟦 봇 변동 | 능력치 |
| `직군` | 🟩 GM | 진입·조사 조건 |
| `오늘추적` | 🟦 봇 | 추적 일일 1회 카운터(0/1) |
| `오늘조사` | 🟦 봇 | 조사 일일 2회 카운터(0~2). **판정 기준은 조사 시트 `로그`**, 이 값은 미러 |
| `출석` | 🟨 공유 | 빈칸 = 오늘 출석 안 함 / `O` = 출석함. **출석 1일1회 판정의 기준**. 컬럼명 = `ATTENDANCE_COMMAND` |

> `관리`는 캐싱 금지. GM은 **직군·능력치 초기값**만 세팅. 소지금·소지품·능력치 변동·`오늘추적`·`오늘조사`·`출석`은 봇이 관리(스케줄러가 00:00 리셋).
> **추적·조사·출석만 시트에 표시를 둔다**(GM이 마을 활동량 트래킹). 나머지 일일 제한(대화·의무실)·대화 상대는 **봇 JSON**(§6).

#### `출석` 컬럼 (공유) — 출석 1일1회의 **단일 기준**
- 빈칸 → 출석 가능. 비어 있지 않으면(`O`) 이미 출석 → 거절. 스케줄러가 00:00 KST에 빈칸으로 되돌린다.
- 기록값은 **알파벳 대문자 O**(U+004F)이지 숫자 0이 아니다.
- 판정은 "빈칸이냐 아니냐"로 한다. `o`·`ㅇ` 등 GM이 다르게 적어 둔 칸도 출석으로 인정한다
  (`O`만 인정하면 그 칸을 빈칸으로 봐서 같은 사람이 두 번 출석하게 된다).
- **시트가 곧 판정 기준이라 GM이 직접 교정할 수 있다.** 칸을 지우면 그날 다시 출석할 수 있고,
  손으로 `O`를 넣으면 봇이 기록한 적 없어도 출석한 것으로 처리된다.
- ⚠️ **이 컬럼이 없으면 봇이 출석을 거절한다(fail closed).** 컬럼이 곧 제한이라,
  없는 채로 진행하면 일일 제한이 사라져 소지금을 무한히 받을 수 있다. GM은 반드시 컬럼을 만들 것.
- 봇 JSON `오늘출석`은 **더 이상 쓰지 않는다**(§6). 이력: 관리시트 MM/DD 마커 → JSON → 이 컬럼.
> **비밀설정**은 별도 컬럼 없이 GM이 `추적` 시트 단서에 직접 써 넣는다(§4 `추적`).
> **입원**=`건강`에서 파생(무저장), **생존여부**=GM 처리(무저장).

### `소문` 워크시트 흐름 (공유)
1. 봇이 `행동로그`의 눈에 띄는 항목을 후보로 적재(`출처=자동`, `상태=후보`, `원본행`=행동로그 행 번호).
2. GM이 골라 `내용` 다듬고 `상태=확정`(직접 `출처=수동` 추가 가능).
3. 소문일(주 1회)에 봇이 `확정` 행을 **무작위 수신자 3~5명**에게 DM → `상태=발송` + `행동로그.소문화=O`.

> **`원본행`은 GM이 건드리지 않는다.** 봇이 후보를 적재할 때 남기는 행동로그 행 번호이고,
> 3단계에서 원본 로그를 되짚어 `소문화=O`를 찍는 데 쓴다.
> 이 열이 없던 시절엔 `내용`과 `요약`을 **문자열 완전일치**로 대조했다 —
> 2단계가 GM에게 시키는 "내용 다듬기"를 하는 순간 대조가 깨져서, 그 사건이
> 소문화 표시를 못 받고 매주 후보로 다시 올라왔다(2026-07-16 수정).
> `원본행`이 비어 있으면(옛 행·수동 소문) 예전처럼 문자열 대조로 폴백한다.

### `고발` 워크시트 (공유)

|------|------|
| 일차, 고발자, 대상, 사유 | 🟦 봇(플레이어 명령으로 append) |

### `이성` 워크시트 (공유) — 이성 임계 문구 자동 발송
| 컬럼 | 담당 | 비고 |
|------|------|------|
| `이름` | — | 캐릭터 |
| `이성문구1` | 🟩 GM | 이성 ≤ 60일 때 보낼 개인 문구 |
| `문구1 발송여부` | 🟦 봇 | 공란/O (보내면 O) |
| `이성문구2` | 🟩 GM | 이성 ≤ 30일 때 보낼 개인 문구 |
| `문구2 발송여부` | 🟦 봇 | 공란/O |

- 봇이 이성 변동 시(및 일일 감소 후) 검사: `이성 ≤ SANITY_MSG1(=60)` & `문구1 발송여부` 공란 → `이성문구1` DM + `발송여부=O`. `이성 ≤ SANITY_MSG2(=30)` & `문구2 발송여부` 공란 → `이성문구2` DM + `발송여부=O`.
- **각 문구 1회만**(발송여부 플래그). 임계값은 env로 조정(초기 60/30).
- `발송여부`가 시트에 있어 슬롯 간 공유 → 중복 발송 없음(락으로 check-and-set). 회복 후 재하락 시 재발송이 필요하면 GM이 발송여부를 비우거나 정책 논의.
- ⚠️ **조사/추적 결과 텍스트의 "이성 왜곡"(마스킹/오정보)** 은 별개 기능이며 임계값도 별도(왜곡≤40/환각≤20, `시너몬트_구현계획.md` §4.7·`AI_API_설계.md`).

> 명세는 `조사봇_개발_가이드.md`, 구현 결정은 `조사봇_구현_결정.md`. 아래는 실제 시트 기준(2026-07-16 실사).

| 워크시트 | 담당 | 컬럼 |
|----------|------|------|
| `진입` | 🟩 GM | 현재 조사 가능 / 조사 오픈 일자 / 장소명 / 진입 시 문구 |
| 장소 시트 9종 | 🟩 GM | 현재 조사 가능 / 조사 오픈 일자 / 조사 가능 직군 / 조사 포인트 / 조사 시 문구 / 획득 아이템 / 개수 / 변동 스탯 / 수치 / 재화 증감 |
| `예외` | 🟩 GM | 캐릭터명 / 장소명 / 포인트명 / 조사 시 문구 |
| `로그` | 🟦 봇 | 일시(MM.DD HH:MM) / 캐릭터명 / 장소명 / 포인트명 / 결과 |

장소 시트 9종: 중앙 광장, 연구소, 광산, 옛 채굴촌, `외곽  시험장`(시트명에 공백 2개), 행정 구역, 주거 구역, 생활 시설, 보안 경계.
직군 5종: 연구자 / 기술공 / 군인 / 행정관 / 가족.

### 핵심 규칙 (봇 동작에 직결)

- **`현재 조사 가능`은 정확히 `가능`일 때만 가능.** 빈칸·기타 값은 전부 불가능.
- **장소 단위 직군 제한은 없다.** 진입 가능 여부는 그 장소 시트의 포인트 접근성에서 파생된다.
  ("보안 경계는 군인만"은 진입 제한이 아니라 모든 포인트가 군인 전용이라 생긴 결과)
- **버전**: 같은 이름의 행이 오픈 일자별로 여러 개 존재할 수 있다(일차별 문구 교체). 스케줄러가 전환.
- **변주**: 같은 이름·**같은 오픈 일자**의 `가능` 행이 둘 이상이면 조사 시 무작위 선택.
  변주 세트는 아이템·스탯·재화를 **통일할 것** (다르면 러너가 유리한 결과까지 반복 조사하는 복권이 된다).
- **`예외`**: 문구 대체 + 접근 부여만 한다. 보상은 기본 행을 따르고, **`불가능`인 포인트는 예외가 있어도 조사 불가**.
- 이름 비교는 **공백을 전부 제거**하고 수행한다(`중앙광장` → `중앙 광장` 매칭).
- `로그`는 봇이 **추가만** 한다. 이 시트가 **일일 조사 횟수 판정과 재시작 시 위치 복원의 기준**이므로 행을 지우면 게임 규칙이 바뀐다.

> 소지품·스탯·재화 변동은 조사 시트가 아니라 **기본 시트 `관리`** 에 반영된다(봇이 처리).
> `관리.오늘조사`는 GM 트래킹용 **미러**일 뿐 판정 기준이 아니다(기준은 `로그`).

## 6. 봇 내부 상태 JSON (시트 아님)

시트에 두지 않는 운영 플래그·카운터는 **봇이 관리하는 JSON 파일**에 보관한다. GM은 만지지 않는다.

- **반드시 디스크 파일**로 영속화(`state/{슬롯}/game_state.json`) — 순수 인메모리면 재시작 시 소실(재시작 복원 요구사항 위반). 변경 시마다 저장(임시파일+rename 원자적 쓰기), 시작 시 로드, 스레드 락.
- **슬롯별 파일**이다. 5슬롯은 별도 프로세스라 한 파일을 공유하면 서로의 기록을 덮어쓴다(실제로 겪은 결함).
- 유틸: `utils/game_state.py`. **`오늘*` 키는 리셋하지 않는다** — 기록한 날짜와 함께
  `{'v': 값, 'd': 'YYYY-MM-DD'}`로 저장하고, 읽을 때 날짜가 오늘이 아니면 없는 것으로 본다.
  → 스케줄러가 죽어 있어도, 어느 슬롯에서 읽어도 자정이 지나면 저절로 풀린다.
- `어제대화상대`는 **저장하지 않는다** — `오늘대화상대`의 날짜에서 파생한다(이월 잡 불필요).
- 스케줄러 00:00 잡이 하는 일은 **`관리` 시트 `오늘추적`·`오늘조사` 리셋**뿐이다(시트는 날짜를 안 들고 있다).
  `관리` 시트 `출석` 빈칸 초기화는 **별도 스케줄러 봇** 담당.

> **추적·조사 카운터(`오늘추적`·`오늘조사`)와 `출석`은 여기 JSON이 아니라 `관리` 시트**에 둔다(§3, GM 트래킹 겸 판정 기준). JSON엔 나머지만.

```json
{
  "<아이디>": {
    "오늘대화여부": 0,
    "오늘고발": 0,
    "오늘의무실": 0,
    "어제대화상대": "",
    "오늘대화상대": ""
  }
}
```
> `오늘대화상대`/`어제대화상대`는 **쉼표 구분 목록**이다. 한 세션에서 2차 상대까지 실제로 대화하면 모두 누적되며, 연속일 금지는 어제 목록의 **누구와도** 다시 대화할 수 없게 막는다.

### ⚠️ 멀티봇(5 프로세스) 주의 — 크로스 슬롯 상태
5개 슬롯은 **별도 프로세스**라 per-slot JSON 파일은 서로 공유되지 않는다. 필드별로 다르게 처리한다:

| 필드 | 쓰는/읽는 슬롯 | 처리 |
|------|-----------|------|
| `오늘대화여부`·`어제/오늘대화상대` | @STORY | 단일 슬롯 → 그 슬롯 JSON. OK |
| `오늘의무실` | @DOCTOR | 단일 슬롯 → 그 슬롯 JSON. OK |
| `오늘추적`·`오늘조사` | @TOWN | **JSON 아님 → `관리` 시트**(GM 트래킹) |
| `출석` | @SYSTEM | **JSON 아님 → `관리` 시트**(판정 기준). 슬롯이 늘어도 정합성 유지 |
| `입원여부` | @TOWN 읽음 | **저장 안 함 → `건강`(시트)에서 파생** (크로스슬롯 문제 소멸) |
| `생존여부` | — | — | **봇 미저장 → GM 처리** (봇은 투표 결과만 기록/알림) |

- **입원여부 = 파생(확정)**: 건강은 시트라 모든 슬롯이 공유. `입원 = (건강 ≤ HEALTH_HOSPITALIZE_THRESHOLD)`로 매번 계산하면 별도 플래그·JSON 불필요. (단, 건강이 회복되면 자동 해제됨 — sticky 입원이 필요하면 논의.)
- **생존여부 = GM 처리(확정)**: 봇은 유죄 과반 판정 결과를 `행동로그`/공지에 남길 뿐 `생존여부`를 저장하지 않는다. 탈락 캐릭터의 활동 차단(멘션 무시 등)은 GM이 수동으로. → 크로스슬롯 저장 문제 없음.

## 7. 요약 — 나(GM)는 무엇을 만지나

**🟩 내가 채우는 워크시트** (콘텐츠·판단):
`명단`·`도움말`·`상점`·`운세`·`커스텀`(기본) / `추적`(단서·비밀설정 포함)·`부탁지령`·`이성`(문구1·2)·`설정`(시스템) / `진입`·장소 시트들(조사)
+ 공유의 GM 몫: `관리`(직군·능력치 초기값), `고발`(처리), `소문`(확정), `이성`(문구)

**🟦 봇이 알아서 하는 워크시트** (열람만):
`행동로그`·`투표`·`추적기록`
+ 공유의 봇 몫: `관리`(소지금·소지품·능력치 변동), `고발`(append), `소문`(후보 적재·발송)
+ **일일 제한**: `관리` 시트 `오늘추적`·`오늘조사`·`출석` + 봇 JSON `오늘대화여부`·`오늘의무실`·대화 상대 (입원=건강 파생 / 생존=GM 처리)(§6)

→ **매일 손대는 것**은 대부분 `설정`·`진입`·장소 시트·`소문`(확정)·`고발`(처리)이고, `추적`·`상점`·직군은 사전에 채워두면 된다. (상세: `운영_준비_가이드.md`)
