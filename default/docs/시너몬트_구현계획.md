## 1. 현재 아키텍처 요약 (설계 근거)

|------|------|------|

| 봇 타입 게이팅 | `registry.get_command_by_keyword()` | 패키지(`default`/`store`/`stats`/`investigate`)별 `BOT_TYPE` 노출/차단. `universal=True`면 우회. **신규 `shinarmont` 패키지 규칙 추가 필요.** |

| 인스턴스/DI | `commands/factory.py` | 생성자 `(sheets_manager, api, **kwargs)`. `investigation_sheets_manager`처럼 **추가 의존성 주입 가능**. |
| 라우팅 | `handlers/command_router.py` | 시스템 명령어 → 커스텀 시트 순. `"X 변경"`→`변경` 자동 라우팅. |
| 멘션/DM 수신 | `handlers/stream_handler.py` | `notification.type=='mention'`만 처리. **DM = `visibility='direct'` 멘션**. `context` 메타데이터에 `visibility`·`original_status`·`notification`·`reply_to_id`. 봇은 **자기가 태그된 멘션만** 인지. |
| visibility 필터 | `config.ALLOWED_VISIBILITY_LEVELS` | 봇 전역 임계값. public 항상 차단. **명령어별 DM 강제는 별도 구현 필요.** |
| DM 발신 | `utils/dm_sender.py` | 즉시/대기열(`queue_dm`). 스트림 매니저가 30초마다 큐 처리. **능동 DM 발송 가능**. |
| 인메모리 상태 | `utils/investigation_state.py` | 사용자별 싱글톤(스레드 안전). **재시작 시 초기화**. |
| 동시성 | `utils/lock_manager.py` | 사용자 락, 두 사용자 ID 정렬 이중 락. `batch_update_cells` 원자적. |

| 변동식 파서 | `utils/dice_parser.py::evaluate_amount` | `10`/`-5`/`1d6`/`3d10+5`/`-(1d6+3)`. 능력치·조사·도박에 재사용. **명령어 [다이스]는 제거해도 파서는 유지.** |

## 2. 태그 ↔ 슬롯 매핑 + `COMMAND_FILTER`

**단일 통합 타입 `shinarmont`** + 슬롯별 필터. 모든 슬롯이 같은 코드를 공유하고 3개 스프레드시트(기본·시스템·조사)를 공유하므로 데이터는 일관.

> 🔴 **레지스트리 수정 필수(`코딩_계획.md` §1.1)**: 기존 registry가 stats/investigate 패키지를 `BOT_TYPE`으로 하드코딩 차단하므로, `bot_type=='shinarmont'`일 때 패키지 게이팅을 우회(allow-all)하도록 `registry.py`를 수정해야 상태확인·스탯변경·사용·진입·조사가 동작한다. `commands/shinarmont/`도 discover 목록에 추가. `INVESTIGATION_ENABLED=True` 전역.

| 태그 | 슬롯 | 역할 | `BOTn_COMMAND_FILTER` | 수신 범위 |
|------|------|------|-----------------------|:---:|
| `@SYSTEM` | BOT1 | 재화·상점·능력치 + **스케줄러 소유** | 출석, 상태 확인, 상점, 구매, 아이템 설명, 사용, 양도, 가방, 스탯 변경, 소지금 관리, 캐시 리셋, 도움말 | 공개 허용 |
| `@TOWN` | BOT2 | 마을 활동 | 진입, 조사, 장소 목록, 추적 | DM 전용 |
| `@STORY` | BOT3 | 스토리·사회 | 대화, 고발, 결과 보고, 교류, 투표 | DM 전용 |
| `@DOCTOR` | BOT4 | 의무실 | 의무실 방문 | DM 전용 |
| `@BAR` | BOT5 | 도박 | 슬롯머신, 크랩스, (후순위)블랙잭 | 공개 허용 |

**`.env` 골격 예시**
```env
ENABLE_MULTI_BOT=True
MASTODON_API_BASE_URL=https://인스턴스
SHEET_ID=공유_스프레드시트_ID
CURRENCY=달러
CURRENCY_EUNNEUN=는

# BOT1 @SYSTEM
BOT1_ENABLED=True
BOT1_ACCESS_TOKEN=...
BOT1_BOT_TYPE=shinarmont
BOT1_COMMAND_FILTER=출석,상태 확인,상점,구매,아이템 설명,사용,양도,가방,스탯 변경,소지금 관리,캐시 리셋,도움말
BOT1_SCHEDULER_OWNER=True         # 신규: 이 슬롯만 스케줄 잡 소유
BOT1_ALLOWED_VISIBILITY=private   # 공개(unlisted/private/direct) 허용

# BOT2 @TOWN
BOT2_ENABLED=True
BOT2_ACCESS_TOKEN=...
BOT2_BOT_TYPE=shinarmont
BOT2_COMMAND_FILTER=진입,조사,장소 목록,추적
BOT2_ALLOWED_VISIBILITY=direct    # DM 전용 슬롯(이중 안전)

# BOT3 @STORY … BOT4 @DOCTOR … BOT5 @BAR (동일 패턴)
```
> `COMMAND_FILTER`/`ALLOWED_VISIBILITY`는 현재 슬롯 접두사(`BOTn_`)로 자동 로드된다(`config.settings`의 싱글봇 폴백 + `bot_config.from_env`). 멀티봇에서 슬롯별 `BOTn_ALLOWED_VISIBILITY`가 로드되는지는 구현 시 확인/보강 필요.

## 3. 코드 정리 (제거 · 개편)

### 3.1 제거 대상 (명령어 파일)
| 파일 | 명령어 | 사유 |
|------|--------|------|
| `commands/default/random_command.py` | `[랜덤]` | 커스텀 `{랜덤:...}`와 중복 |
| `commands/default/dice_command.py` | `[NdM]` 다이스 | 기획에 없음. 도박은 전용 명령. **`utils/dice_parser.py`는 유지**(내부 사용). |
| `commands/store/money_check_command.py` | `[소지금]` | `[가방]`·`[상태 확인]`과 중복 |

> 라우터의 `parse_command_from_text`가 `[2d6]`를 자동으로 `['다이스', ...]`로 바꾸는 특례가 있다. 다이스 명령어 제거 시 이 특례도 함께 제거하거나, "미등록 명령" 응답이 나오지 않도록 정리한다.

### 3.2 개편 대상
- **`[출석]` = 운세 + 3달러 (통합)** — `commands/store/attendance_command.py`를 개편:
  - 하루 1회, `운세` 워크시트에서 오늘의 문구 1줄 선택 + 소지금 +3달러.
  - **시트에 출석 기록을 남기지 않고 봇 내부에서 처리·기록**(결정 C). → 인메모리 일일 집합(날짜 키). ⚠️ 재시작 시 초기화되어 재수령 여지(허용 — §9).
  - **`[운세]` 단독 명령어는 제거**(운세는 출석에 통합, §9).
- **`utils/daily_reset.py`** — 총애도/자백 로직 폐기 후 시너몬트 스케줄러로 재작성(§4.1). 또는 신규 `utils/shinarmont_scheduler.py`.

### 3.3 (선택) 파일 경량화
각 명령어/유틸 파일 하단의 `get_*_migration_guide()`, `if __name__=="__main__"` 데모 블록, `show_*_info()` 등은 런타임에 불필요. 제거하면 파일이 가벼워지나 기능 영향은 없다. **별도 정리 작업으로 분리 권장**(리스크 낮음, 범위 큼).

## 4. 공통 신규 인프라 (상세 설계)

### 4.1 스케줄러 (`utils/shinarmont_scheduler.py`) 🔴
- **배선**: `main.py::_initialize_bot_systems` 이후, `BOTn_SCHEDULER_OWNER=True`인 슬롯에서만 백그라운드 스레드로 시작(`OperationPeriodMonitor` 패턴). → 멀티봇 5중 실행 방지.
- **엔진**: `apscheduler`(설치됨)로 KST 크론 명시 권장. `sheets_manager`·`dm_sender`·`api`를 주입.
- **등록 잡**
  | 주기 | 작업 | 참조 |
  |------|------|------|
  | 매일 00:00 KST | 능력치 감소(§4.8), 일일 카운터 리셋(§4.3), 입원 상태 재평가 | 관리 시트 일괄 |
  | 매주 지정/무작위 일 | 소문 발송(§5.14) | 행동로그 → DM |
  | (선택) 특정 일차 | 부탁/지령 배포, 투표 집계·처분 | 설정 시트 |
- **일일 감소 동시성**: 명령어와의 lost-update를 막기 위해 **사용자별 락 안에서 재조회→감소→반영**한다(명령어와 같은 `lock_manager`). 00시 저부하라 사용자당 1회 재조회를 허용. (초기안의 "열 단위 일괄 batch"는 락을 우회해 명령어와 경합하므로 폐기.)

### 4.2 DM 전용 게이팅 (`utils/dm_guard.py` 또는 데코레이터) 🔴
```python
# 개념: 명령어 execute 진입부
if context.get_metadata('visibility') != 'direct':
    return CommandResponse.create_error("이 명령어는 DM(다이렉트 메시지)로만 사용할 수 있습니다.")
```
- 데코레이터 `@dm_only`로 재사용. 대상: 진입·조사·추적·대화·교류·의무실·고발·투표·결과 보고.
- 슬롯 `BOTn_ALLOWED_VISIBILITY=direct`와 **이중 안전**.

### 4.3 일일 제한 저장 (분리) 🔴
- **추적·조사 = `관리` 시트 카운터**: `오늘추적`(0/1), `오늘조사`(0~2). GM이 마을 활동량을 시트에서 트래킹. (락+update_cell)
- **나머지 = 봇 내부 JSON**(`utils/game_state.py`, 디스크 영속): `오늘대화여부`·`어제/오늘대화상대`·`오늘고발`(@STORY), `오늘의무실`(@DOCTOR). 전부 단일 슬롯.
  (`오늘출석`은 폐기 — 출석 1일1회는 `관리` 시트 `출석` 컬럼이 판정한다.)
- API: `check_and_set(user_id, key, limit)` / `get`/`set` (스레드 락 + 원자적 쓰기).
  세션성(대화 6멘션·블랙잭 진행)도 **디스크 영속**으로 전환했다(2026-07-16) —
  봇을 껐다 켜도 판·타래가 끊기지 않아야 하고, 블랙잭은 베팅이 이미 차감돼 있다.
- 스케줄러가 00:00에 **JSON `오늘*` + 관리 시트 `오늘추적`·`오늘조사`** 리셋, `오늘대화상대→어제대화상대` 이월.
- ⚠️ **멀티봇(5 프로세스)**: 크로스슬롯 상태는 저장 안 함 — 입원=`건강`(시트) 파생, 생존여부=GM 처리. `스프레드시트_구성.md` §6.

### 4.4 행동 로그 워크시트 `행동로그` 🔴 (추적·소문의 소스) — **스키마·대상은 `코딩_계획.md` §1.3 확정본 사용**
| 컬럼(9열, 순서 고정) | 형식 | 비고 |
|------|------|------|
| `일시` | `YYYY-MM-DD HH:MM:SS` | `get_current_time()` |
| `일차` | 정수 | 설정 시트 `현재 일차` |
| `종류` | 추적/고발/결과보고/교류/의무실/투표결과 | |
| `행위자` | **이름** | |
| `대상` | 이름/장소/'-' | |
| `요약` | 문자열 | 소문/추적 노출 한 줄 |
| `상세` | 문자열/'-' | 농도·사유·회복량 |
| `능력치변동` | 문자열/'-' | "이성 -4" 등 |
| `소문화` | 공란/O | 소문 발송 시 |
- 캐싱 금지. **기록 대상 = 추적·고발·결과보고·교류·의무실** 실행 시 1행 append. **조사·대화는 로그 안 함**, 투표는 과반 확정 시 집계 1줄(`종류=투표결과`). `action_log.append(...)` 헬퍼가 9열 순서 보장.

### 4.5 직군(Role) 시스템 🔴
- `명단`(또는 `관리`)에 `직군` 컬럼. 직군별 목표/비밀은 `명단` 또는 별도 `직군` 워크시트.
- 진입/조사 시트의 `허용 직군`(쉼표 구분)과 대조하는 공통 헬퍼 `role_allows(user_role, allowed_field)`.

### 4.6 대상 지정 + DM 릴레이 헬퍼 (`utils/target_helpers.py`) 🔴
- `TransferCommand`의 대상 조회/이중 락/DM 저장을 일반화:
  - `resolve_target(context, keyword_index)` → 키워드명 또는 `status.mentions`에서 대상 (이름/아이디) 해석.
  - 자기 자신·미등록 방지 표준 에러.
  - `queue_dm(receiver_id, message)`로 알림.
- 추적·대화·교류·고발·투표가 재사용.

### 4.7 이성 왜곡 엔진 (`utils/distortion.py`) 🔴 — **단계적(결정 D)**
- **입력**: 출력 텍스트 + 대상 이성 수치.
- **구간별 처리** (임계치는 §9-B에서 확정; 아래는 초안):
  | 이성 구간 | 처리 | 예 |
  |-----------|------|----|
  | 정상(> 왜곡임계) | 원문 그대로 | — |
  | 경고(왜곡임계 ~ 환각임계) | **부분 마스킹**: 명사/숫자 일부를 `▓`·`…`로 가림, 강도는 낮을수록 ↑ | "간호사가 **▓▓**를 들고 있다." |
  | 위험(≤ 환각임계) | **오정보 치환 + 환각 연출**: 사전/규칙 기반으로 일부 정보를 그럴듯한 거짓으로 대체, 서두에 환각 톤 문장 삽입 | "(환청이 들린다…) 그는 **웃으며** 다가온다." |
- **오정보 소스**: 규칙 기반(숫자 ±랜덤, 인물/장소 명을 명단·장소 목록에서 무작위 치환) → GM 오해 관리 부담 최소화. 세밀 제어가 필요하면 `설정` 시트에 치환 사전 컬럼 추가.
- **적용 지점**: 조사·추적·소문 출력. 상태확인/상점 등 사실성 필요한 UI엔 미적용.
- **결정성(확정)**: 매번 다르게(시드/캐시 고정 없음). `changes`는 매 호출 로그. (AI 설계 §3)

### 4.8 능력치 게이트 (`utils/stat_gate.py`) 🔴
- **일일 감소**: 스케줄러가 `건강`·`이성`을 매일 소량 감소(하한 0).
- **입원 판정(파생)**: `입원 = (건강 ≤ HEALTH_HOSPITALIZE_THRESHOLD)`를 매번 계산(별도 플래그 저장 안 함, 건강은 시트라 모든 슬롯 공유). 입원 중이면 마을 활동 차단(§9). `[의무실 방문]`으로 건강 회복 → 자동 해제.
- **왜곡 강도**: 이성 값을 §4.7 엔진에 전달.

### 4.9 이성 임계 문구 자동 발송 (`이성` 워크시트) 🔴
- **목적**: 이성이 임계 이하로 떨어지면 봇이 **개인별 문구**를 자동 DM. (기획: "이성이 낮아지면 환각/망상")
- `이성` 시트(시스템): `이름`, `이성문구1`, `문구1 발송여부`, `이성문구2`, `문구2 발송여부`. 문구는 GM 작성.
- 봇: 이성이 바뀔 때(및 일일 감소 후 스케줄러 스윕) 검사 —
  - `이성 ≤ SANITY_MSG1_THRESHOLD`(=60) & `문구1 발송여부` 공란 → `이성문구1` DM + `발송여부=O`.
  - `이성 ≤ SANITY_MSG2_THRESHOLD`(=30) & `문구2 발송여부` 공란 → `이성문구2` DM + `발송여부=O`.
- **각 1회만**(발송여부 sticky). `발송여부`가 시트라 슬롯 간 공유 → 락으로 check-and-set, 중복 발송 방지.
- 왜곡(§4.7, 40/20)과는 **별개 기능·별개 임계**. 값은 env(`SANITY_MSG1_THRESHOLD`/`SANITY_MSG2_THRESHOLD`, 초기 60/30).

## 5. 명령어 상세 스펙

> 공통: 상태 변경 명령은 **락 획득 후 재조회 → 검증 → `batch_update_cells` → 캐시 무효화**. 대상 지정 명령은 §4.6 헬퍼 사용. DM 전용은 §4.2 게이트.

### 5.1 `[출석]` — 운세 + 3달러 (개편) ✅→🟡
- 형식: `[출석]`. 하루 1회.
- 흐름: 인메모리 일일 집합 확인 → 이미 수령이면 안내. 아니면 `운세` 시트에서 1줄 선택 + 소지금 +`ATTENDANCE_AMOUNT`(=3) → 응답 "오늘의 운세: … / +3달러". 봇 내부 기록.
- 결정 C 반영. 저장 방식 §9-J.

### 5.2 `[상태 확인]` ✅
- 기존 `peek_status`. `PEEK_HEADER=소지금,소지품,건강,이성`로 노출.

### 5.3 상점/구매/아이템 설명/사용/양도/가방 ✅
- 기존 그대로. 회복 아이템(보급품/진통제/안정제)을 `상점` 시트에 `스탯`=건강/이성, `수치`=회복식으로 등록하면 `[사용]`이 능력치 회복.
- 양도: `PREMIUM_TRANSFER_*_ENABLED=True`.

### 5.4 `[진입/장소명]` (확장) 🟡
- 기존 + **직군/조건 필터**: `진입` 시트에 `허용 직군`·`필요 스토리 단계`·`활성 조건` 컬럼. 사용자 직군/현재 일차/환경과 대조 후 진입 허용. DM 전용.

### 5.5 `[조사/포인트]` (확장) 🟡
- DM 전용. **하루 2회**(`관리` 시트 `오늘조사` 카운터, 0~2).
- 기존 조사 로직 + 장소 워크시트에 `허용 직군`·조건 컬럼 → 필터. 결과 텍스트에 **이성 왜곡(§4.7)** 적용. **조사는 행동로그에 남기지 않음**(§4.4).

### 5.6 `[추적/캐릭터명]` 🔴
- DM 전용. **하루 1회**(`관리` 시트 `오늘추적` 카운터, 0/1).
- **단서 풀 방식(확정)** — 두 워크시트(형식 상세: `추적_시트_형식.md`):
  - `추적` 시트: 인물(대상)별 `추적1~추적5` 열에 단서 텍스트(빈 칸 허용, 0~5개).
  - `추적기록` 시트: 추적자별 행에 받은 `{대상}{번호}` 토큰 콤마 목록(봇 자동 기록).
- 동작: 대상 Y의 비어 있지 않은 단서 − 추적자 X가 이미 받은 Y 단서 = 가용 → 랜덤 1개 → `추적기록`에 append → DM. 전부 받았으면 "더 알아낼 것이 없다.".
- **추적자별 중복 없음**, 재시작에도 시트로 유지. 결과 텍스트에 **이성 왜곡 적용**. 자기 자신·미등록 방지. 운영: `운영_준비_가이드.md` §5.

### 5.7 `[대화] @상대` (비밀 대화) 🔴
- DM 전용, `@STORY`. 하루 1회(`오늘대화여부`), 같은 상대 연속일 금지(`어제대화상대`/`오늘대화상대`).
- 세션: 봇이 태그된 첫 멘션에서 상대·시작 기록(인메모리 세션) → 이후 멘션 카운트, **캐릭터당 3회·총 6회** 초과 시 안내/종료. 대화 사실을 행동로그에 요약 기록.
- 카운트 방식 세부 §9-G.

### 5.8 `[교류/농도] @상대` 🔴
- DM 전용, `@STORY`. 농도 1~5 검증.
- 회복량 = `농도 × EXCHANGE_SANITY_PER_LEVEL`. **양쪽 이성 회복**(이중 락, batch, 상한 100). 상대에게 DM 알림. **일일 제한 없음**(§9).

### 5.9 `[의무실 방문]` 🔴
- DM 전용, `@DOCTOR`. **1일 1회 무료**(§9).
- **회복은 시작이 아니라 대화 종료 시 1회.** 방문하면 러셀 선생과 답글 스레드로 진료 대화. **의사가 대화 흐름을 보며 스스로 진료를 마무리**한다(최소 `DOCTOR_TURNS_MIN`=2, 이상 `IDEAL`=3~6, 하드 상한 `DOCTOR_MAX_TURNS`=8; concluding 판정은 AI, 경계는 코드가 강제). 마무리 시 **처치 결과**를 결정해 `관리`의 건강/이성에 직접 반영:
  - `진통제`→건강↑ · `안정제`→이성↑ · `상담`→이성↑(건강 소폭) · `과잉심문`(너무 캐물은 날)→이성↓·건강↑ · `경과관찰`→변화 미미.
  - 처치·수치는 **AI가 대화 맥락으로 결정**(`ai_client.doctor_treatment`, 구조화 출력). AI 꺼짐/실패 시 **규칙 폴백**(낮은 능력치 회복, '과잉심문'은 AI만 판정).
  - 변동은 `DOCTOR_TREAT_DELTA_MIN/MAX`로 클램프, 능력치 0~100 유지. 건강 회복으로 입원 자동 해제.
- **행동로그 기록**(처치 요약 1줄 → 소문 소스). AI 의사 대화·페르소나는 `docs/AI_API_설계.md`·`docs/의사_페르소나.md` 참조.
- **다중 타래**: 세션은 session_id로 관리(사용자당 여러 개 공존). 봇이 보낸 답글 status_id를 `utils/reply_threads`에 등록해, 사용자가 **대괄호 없이 답글로 이어가도** 그 타래로 라우팅된다(핸들러 `_resolve_routing` + 전송 후 `commit`). 스레드 안에서 `[대화 끝내기]`처럼 명시 명령을 쓰면 그게 우선.
- **일차 카운팅**: `오늘의무실`은 방문을 **시작한 날** 기준 소모(자정마다 리셋). 17일에 시작한 타래를 18일 새벽까지 이어가도 17일로 카운트되며, 18일에 새 `[의무실 방문]`을 또 쓸 수 있다(새 방문은 이전 타래를 종료시키지 않음).
- **[대화 끝내기]**(@DOCTOR, DM): 진행 중인 진료를 **처치 없이** 강제 종료(방문 횟수는 이미 소모됨). 스레드 답글로 오면 그 타래를, 아니면 최근 진행 세션을 종료.
- 응답 메시지는 이모지/기호 없이 **플레인텍스트**. 세션은 프로세스 인메모리(재시작 시 소실).

### 5.10 `[고발/캐릭터명]` + 본문 사유 🔴
- DM 전용, `@STORY`. **하루 1회**(JSON `오늘고발`).
- 사유는 `context.original_text`에서 대괄호 이후 텍스트 → **1줄 이상** 검증. 대상 유효성 확인.
- `고발` 워크시트에 (일차, 고발자, 대상, 사유) 기록 → 고발자 소지금 +`ACCUSE_REWARD`(=50). 행동로그에도 요약(소문화 가능). 허위 과다 판정은 GM/추후.

### 5.11 `[투표/유죄]` · `[투표/무죄]` 🔴
- DM 전용, `@STORY`. 단상 명단(설정 시트/고발 집계)에 대해 투표.
- `투표` 워크시트에 (일차, 대상, 투표자, 표). **1인 1표**(시트 조회로 중복 방지).
- 집계: 스케줄/관리자 명령으로 대상별 유죄율 → 과반이면 **결과를 `행동로그`/공지에 기록**. **실제 처분(탈락 반영·차단)은 GM 수동**(봇은 `생존여부`를 저장하지 않음, §9).
- 대상 지정 방식(단일 단상 vs `[투표/유죄/대상]`) §9.

### 5.12 `[결과 보고]` + 본문 🔴
- DM 전용, `@STORY`. 본문 1줄 이상.
- 봇이 보고를 `부탁지령` 시트/행동로그에 저장. 보상 자동/GM 검토 §9-F.

### 5.13 도박 `@BAR` 🔴
- **슬롯머신 `[슬롯머신]`**(우선): 베팅액 파싱 → 릴 랜덤 → 배당표로 정산. 락+batch로 소지금 갱신. 단발.
- **크랩스 `[크랩스]`**(우선): 베팅 → 주사위 규칙 판정 → 정산. 단발 또는 2페이즈(포인트).
- **블랙잭 `[블랙잭]`**: **딜러(NPC) vs 플레이어 1인 게임**. 히트/스탠드 다회 상호작용 →
  게임 세션(스레드 안전, **디스크 영속**) + 답글 스레드 진행. 로깅 접두사 `[블랙잭]`.
  첫 턴에는 `[더블다운]`(베팅 2배·1장·강제 종료)/`[서렌더]`(절반 환불) 가능.
  딜러 규칙·배당률은 참조 구현(bot-cm-default/commands/casino/blackjack)과 **전수 대조로 일치 확인**
  (546개 핸드 조합의 합·소프트 판정, 딜러 H17 히트 판단, 배당 배수 전부).
- 베팅 상한/일일 손실 한도 옵션.

### 5.14 소문 (GM 큐레이션 + 자동 발송) 🔴
- **큐레이션 방식(확정)**: 봇이 `행동로그`의 눈에 띄는 항목을 `소문` 시트에 **후보**로 자동 적재(`출처=자동`, `상태=후보`) → GM이 골라 문구 다듬어 `상태=확정`(직접 `출처=수동` 추가 가능).
- 스케줄러가 소문일(주 1회)에 `확정` 행을 **무작위 수신자 3~5명**에게 `dm_sender`로 발송(대상 지정 없음) → `상태=발송` + `행동로그.소문화=O`.
- 수신자 이성 낮으면 왜곡 적용. "미확인 정보" 톤 고정 문구. 운영 상세: `운영_준비_가이드.md` §6.

### 5.15 (자동) 능력치 일일 감소 🔴
- §4.8. 스케줄러 매일 00:00. 하한 0, 입원 판정 갱신.

## 9. 결정 로그 (확정 2026-07-14)

거의 모든 항목이 확정되었다. 남은 것은 GM 콘텐츠(직군 목록) 1건과 사소한 저장 방식 1건뿐.

| 항목 | 확정 |
