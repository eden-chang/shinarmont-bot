# Google Sheets 트래킹 설계 — 커뮤니티 진행 상황을 한눈에

> 봇이 꺼졌다 켜져도 **시트만으로** 진행 상황과 제약을 복원할 수 있고, GM이 보기 쉽고 관리하기 쉬운 시트 구조.
> 기록 대상: **추적 · 고발 · 결과 보고 · 교류 · 투표 · 의무실 방문**. (시스템 명령 = 상점/구매/사용/양도/상태확인/출석 = **기록 안 함**)
> 작성 2026-07-14. 기존 시트: 조사 자동봇 시트(별도) + 기본 시트(명단·도움말·관리·상점·커스텀·운세).

---

## 0. 결론 (권장 구조)

두 종류의 시트를 분리해서 쓴다 — **"흐름을 읽는 로그"** 와 **"상태를 복원하는 스냅샷"**.

| 시트 | 성격 | 왜 |
|------|------|----|
| **`행동로그`** | 타임라인 로그(append-only) | 6종 행동을 시간순 한 줄씩 → GM이 스토리 피드처럼 읽음. 소문의 소스. |
| **`투표`** | 집계 전용 로그 | 표가 많고 1인1표·과반 판정이 필요 → 전용 시트가 세는 데 깔끔. |
| **`고발`** | 사유 보관 + 단상 산출 | 사유 본문 보관, 특정 일차 단상 명단 계산. |
| **`관리`(기존 확장)** | **라이브 상태 스냅샷** | 능력치·입원·**일일 카운터**·대화 상대 → 재시작 복원의 핵심. |
| **`설정`** | 전역 진행 스냅샷 | 현재 일차·단상 명단·오늘 이벤트 → GM 제어판 + 봇 복원. |

추가 시트(운영·콘텐츠용, `운영_준비_가이드.md`·`추적_시트_형식.md`와 연동):
- **`추적`**(GM 입력) — `이름`(대상) + `추적1~추적5`(단서 텍스트, 빈 칸 허용). GM이 인물별 최대 5개 단서를 채운다.
- **`추적기록`**(봇 내부) — `이름`(추적자) + `추적기록`(받은 `대상번호` 콤마 목록). 추적자별 중복 없이 배분하기 위한 이력(재시작 복원).
- **`소문`**(GM 큐레이션) — 일차·출처·내용·상태(후보/확정/발송). 봇이 후보 적재 → GM 확정 → 봇 무작위 발송(대상 지정 없음).

핵심 원칙 3가지:
1. **로그(무슨 일이 있었나)** 와 **상태(지금 어디까지 왔나)** 를 섞지 않는다.
2. **재시작 복원에 필요한 값은 시트 또는 봇 JSON 파일**(둘 다 디스크 영속)에 둔다. 순수 인메모리(RAM) 금지. → 능력치·투표·추적기록=시트 / 일일 제한·대화 이력=봇 JSON.
3. 모든 로그 시트는 **컬럼 고정 + 1행 헤더 / 2행 설명 / 3행부터 데이터** 규칙 유지.

## 1. `행동로그` — 통합 타임라인 (5종)

추적·결과보고·교류·의무실·고발(요약)을 한 줄씩 append. **투표는 여기 넣지 않는다**(§2, 너무 많음).

| 컬럼 | 형식 | 예 |
|------|------|----|
| `일시` | `YYYY-MM-DD HH:MM:SS` | 2026-07-20 21:14:03 |
| `일차` | 정수 | 4 |
| `종류` | 열거 | 추적 / 결과보고 / 교류 / 의무실 / 고발 |
| `행위자` | 이름(또는 아이디) | 한참 |
| `대상` | 이름/장소/'-' | 울로 |
| `요약` | 한 줄(봇이 사람 읽기 좋게 생성) | 한참이 울로를 추적했다 |
| `상세` | 본문/농도/결과 등 | 사유: "밤마다 뒷문으로…" / 농도 3 / 회복 건강+8 |
| `능력치변동` | 문자열/'-' | 이성 -4 |

- **왜 통합인가**: GM이 "커뮤에서 무슨 일이 벌어지는가"를 **한 탭에서 시간순**으로 읽는 게 가장 편하다. `종류`로 필터하면 특정 행동만 볼 수 있다.
- 이질적 필드(교류의 농도, 고발의 사유)는 `상세` 한 칸에 사람이 읽을 형태로 몰아넣어 컬럼 수를 8개로 유지 → **간결**.
- **소문 소스**: 소문 발송은 이 시트에서 표본을 뽑는다. `소문화` 컬럼을 하나 더 두어(공란/O) 이미 소문 낸 행을 표시하면 중복 방지.
- 봇은 `SheetsManager.append_row('행동로그', [...])` 로 기록(기존 메서드 재사용).

> **읽기 편하게(운영 팁)**: Google Sheets **필터 보기(Filter views)** 를 종류별로 미리 만들어 두면(예: "교류만", "고발만") GM이 클릭 한 번으로 좁혀 본다. 헤더 2행 고정(틀 고정)도 함께.

## 2. `투표` — 집계 전용

투표는 인원×일차만큼 행이 쌓여 통합 로그에 섞으면 지저분하다. 전용 시트에서 세는 게 깔끔하고, 1인1표 검사·과반 판정도 여기서 조회 한 번으로 끝난다.

| 컬럼 | 형식 | 용도 |
|------|------|----|
| `일차` | 정수 | 어느 날 투표 |
| `대상` | 이름 | 단상에 오른 인물 |
| `투표자` | 이름 | 1인1표 |
| `표` | 유죄 / 무죄 | |
| `일시` | 타임스탬프 | 순서·감사 |

- **1인1표**: 투표 명령이 `(일차, 대상, 투표자)` 조합 존재 여부를 조회 → 중복 차단. 재시작해도 시트로 복원.
- **과반 판정**: 스케줄/관리자 집계가 `(일차, 대상)`별 유죄/무죄 카운트 → 과반이면 결과를 `행동로그`/공지에 기록. **탈락 반영·연출은 GM 수동**(봇은 생존여부 저장 안 함).
- 요약 1줄을 `행동로그`에 남기고 싶다면 **집계 결과만**(예: "N일차 울로 유죄 과반 → 처분") 남기고, 개별 표는 `투표` 시트에만.

## 3. `고발` — 사유 보관 + 단상

| 컬럼 | 형식 | 용도 |
|------|------|----|
| `일차` | 정수 | |
| `고발자` | 이름 | |
| `대상` | 이름 | |
| `사유` | 본문 | 1줄 이상, 원문 보관(허위 판정·소문 소스) |
| `처리` | 공란/보상지급/단상/무효 | 관리자 처리 상태 |

- 고발 시 여기에 append + 고발자 +50달러(관리 시트). 동시에 `행동로그`에 "한참이 울로를 고발" 1줄 요약(사유 원문은 `고발` 시트에).
- **단상 명단 산출**: 특정 일차에 `대상`별 고발 수를 집계하거나 GM이 `처리=단상`을 표시 → `설정`의 단상 명단으로 반영 → 투표 대상이 된다.

## 4. `관리` 시트 vs 봇 JSON — 상태 분리

캐릭터의 **지속 데이터는 `관리` 시트**, **운영 플래그·카운터는 봇 내부 JSON**으로 나눈다.

**`관리` 시트 컬럼**
| 컬럼 | 형식 | 복원되는 상태 |
|------|------|--------------|
| 이름, 아이디 | 문자열 | 명단 연동 |
| `소지금` `소지품` | 정수/문자열 | 재화·인벤토리 |
| `건강` `이성` | 정수 | 능력치 |
| `직군` | 문자열 | 진입/조사 조건(GM 세팅) |
| `오늘추적` | 0/1 | 추적 1일1회 (@TOWN) — **시트, GM 트래킹** |
| `오늘조사` | 0~2 | 조사 1일2회 (@TOWN) — **시트, GM 트래킹** |

**봇 내부 JSON (시트 아님, 디스크 영속)** — `utils/game_state.py`
| 키 | 형식 | 용도 |
|----|------|------|
| ~~`오늘출석`~~ | — | **폐기** → `관리` 시트 `출석` 컬럼(빈칸/O)이 판정 기준 (@SYSTEM) |
| `오늘대화여부` | 0/1 | 비밀대화 1일1회 (@STORY) |
| `오늘고발` | 0/1 | 고발 1일1회 (@STORY) |
| `오늘의무실` | 0/1 | 의무실 1일1회 (@DOCTOR) |
| `어제대화상대` `오늘대화상대` | 이름 | 연속일 대화 금지 (@STORY) |
| `현재장소`(선택) | 장소명 | 진입 상태 복원 |

- **추적·조사 카운터만 `관리` 시트**(GM 트래킹). 나머지 일일 제한은 봇 JSON.
- **입원여부**는 저장하지 않고 `건강 ≤ 임계`에서 **파생**(건강은 시트라 모든 슬롯 공유).
- **생존여부(유죄 처분)**는 봇이 저장하지 않는다. 봇은 투표 결과만 `행동로그`/공지에 기록하고, 탈락 반영은 GM 수동.
- **비밀설정**은 `관리`에 두지 않고 GM이 `추적` 시트 단서에 직접 써 넣는다.
- 스케줄러가 매일 0시에 **JSON `오늘*` + 관리 시트 `오늘추적`·`오늘조사`**를 0으로, `어제대화상대 ← 오늘대화상대` 이월.
- ⚠️ 멀티봇(5 프로세스) 크로스슬롯 이슈는 `스프레드시트_구성.md` §6 참조.
- **`이성` 시트(시스템)**: 이성 임계(≤60/≤30) 시 봇이 개인 문구를 자동 DM(각 1회, `발송여부` 플래그). GM이 문구 작성. → `스프레드시트_구성.md` §4.

> `관리`는 **캐싱 금지**(항상 `use_cache=False`). 변경 후 `invalidate_user_cache()`.

## 5. `설정` — 전역 진행 스냅샷 (GM 제어판)

로그가 아니라, "지금 시스템이 어디까지 왔나"를 한눈에 보고 봇이 참조하는 작은 표.

| 항목 | 값 예 | 용도 |
|------|-------|------|
| `현재 일차` | 4 | 실제 날짜 기반(2026-07-17=1일차)이면 봇이 자동 계산하지만, GM이 수동 오버라이드하고 싶을 때 |
| `오늘의 환경` | 안개 | 조사 조건 필터 |
| `단상 명단` | 울로, 미르 | 투표 대상 |
| `소문 요일` | 수 | 주간 소문 발송일 |

- 한 시트에 `항목 | 값` 2열로 두면 GM이 편집하기 쉽다.

## 6. 재시작 복원 매핑 (요구사항 직접 대응)

"봇이 꺼졌다 켜져도 트래킹" → 어떤 상태가 어디서 복원되는지 (시트 **또는** 봇 JSON 파일):

| 복원할 것 | 저장 위치 |
|-----------|----------|
| 능력치(건강·이성)·소지금·소지품·직군 | `관리` 시트 |
| 입원 | **파생**(`건강` ≤ 임계, 저장 안 함) |
| 일일 제한(추적·조사) | `관리` 시트(`오늘추적`·`오늘조사`) |
| 일일 제한(출석·대화·고발·의무실) | **봇 JSON** 파일 |
| 연속일 대화 금지(어제/오늘 대화상대) | **봇 JSON** 파일 |
| 생존여부(유죄 처분) | **봇 미저장 → GM 처리**(봇은 투표 결과만 기록) |
| 투표 집계·1인1표 | `투표` 시트 조회 |
| 단상 명단·현재 일차·환경 | `설정` 시트 |
| 고발 사유·처리 | `고발` 시트 |
| 무슨 일이 있었나(피드) | `행동로그` 시트 |
| 진입 현재 장소 | 봇 JSON(선택) |

→ 봇 JSON은 **디스크 파일로 영속화**(순수 인메모리 금지). 순수 인메모리로 두는 것은 "진행 중 의무실/대화 세션의 임시 턴"뿐. 그 외 게임 진행 상태는 시트 또는 JSON에서 복원된다.

## 7. 왜 이 구조가 "간결·보기 쉬움·관리 쉬움"인가

- **간결**: 신규 로그 시트 3개(`행동로그`·`투표`·`고발`)만 추가. 나머지는 기존 `관리` 확장 + 작은 `설정`.
- **보기 쉬움**: `행동로그`이 스토리 피드처럼 읽히고, 필터 보기로 종류별 축소. 집계가 필요한 투표/고발만 분리.
- **관리 쉬움**: 컬럼 고정·사람이 읽는 `요약`을 봇이 미리 써 줌. GM은 `설정`·`고발.처리`만 만지면 흐름을 통제.
- **안전**: 상태(관리/설정)와 로그(행동로그/투표/고발)를 분리해, 로그가 커져도 상태 조회 성능·가독성에 영향 없음.

## 8. 결정 로그 (확정 2026-07-14)

- **행위자·대상 표기 = 이름만.** `행동로그`/`투표`/`고발`의 행위자·대상 컬럼은 이름을 쓴다. (동명이인이 실제로 문제되면 그때 아이디 컬럼을 덧붙인다.)
- **투표는 `행동로그`에 넣지 않고 `투표` 시트에만.** `행동로그`에는 집계 결과 1줄만 남긴다(예: "N일차 울로 유죄 과반 → 처분").
- **상세 내용 = 요약만.** 의무실 대화 원문·AI 오정보 `changes`는 전문을 남기지 않고 **`행동로그.상세`에 한 줄 요약**만. (소문으로 샐 수 있으므로 요약이 안전하고 시트도 가벼움.)
- **AI 오정보 `changes` 위치 = `행동로그.상세`(요약).** 별도 GM 전용 시트를 만들지 않는다. "무엇이 환각이었나"는 요약 수준으로 추적.
- **소문 표본 정책**: 주 1회, `행동로그`(소문화 미표시 행)에서 **3~5건 표본**, **무작위 3~5명**에게 발송, 발송분은 `소문화=O` 표시. (구현계획 §5.14와 동일.)

> 위 결정으로 `행동로그` 시트는 "한 줄 요약 중심의 가벼운 스토리 피드"로 유지된다 — 무거운 전문은 저장하지 않는다.
