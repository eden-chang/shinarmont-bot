# 시너몬트 조사 자동봇 개발 가이드

마스토돈 커뮤니티용 조사 자동봇의 구현 지시서다.
구글 스프레드시트를 데이터베이스로 사용하고, 마스토돈 계정으로 명령어를 받아 응답한다.
아래 명세를 우선하되, 명세에 없는 세부 구현은 합리적인 범위에서 재량으로 결정하고 결정 사항을 문서화할 것.

## 0. 시스템 개요

- 러너(플레이어)가 봇 계정을 태그한 멘션 또는 DM으로 명령어를 보낸다
- 봇은 명령어를 파싱해 스프레드시트를 읽고, 결과 문구를 답글로 보낸 뒤, 로그와 스탯 변동을 시트에 기록한다
- 별도의 스케줄러가 정해진 일시에 조사 포인트를 자동 개방한다
- 소문, 추적, 고발, 투표, 도박은 이 봇의 범위가 아니다. 다른 봇이 담당한다. 이 봇은 장소 목록, 진입, 조사만 처리한다

## 1. 기술 전제

- 마스토돈 API: 스트리밍(user 타임라인)으로 멘션 수신. 답글은 원문과 같은 공개 범위로 발송하되, DM으로 온 명령은 DM으로 답한다
- 구글 시트 API: 서비스 계정 인증. 읽기와 쓰기 모두 필요
- 시간대: 전부 Asia/Seoul (KST) 기준
- 시트 API 쿼터를 고려해 읽기는 캐시(권장 TTL 30~60초)를 두고, 쓰기는 즉시 반영한다. 단 '현재 조사 가능'과 스탯처럼 정합성이 중요한 값은 명령 처리 시점에 재검증할 것

## 2. 스프레드시트 구조

공통 주의사항:
- 모든 시트는 1행이 컬럼명, 2행이 설명(회색 안내문)이고 실제 데이터는 3행부터 시작한다. 파싱 시 2행을 데이터로 읽지 않도록 주의
- '현재 조사 가능' 컬럼이 빈칸인 행은 '불가능'으로 취급한다. '가능'이라는 정확한 문자열일 때만 가능이다 (진입 시트와 장소 시트 공통)
- 이름 비교(장소명, 포인트명, 캐릭터명)는 앞뒤 공백 제거 후 수행하고, 명령어 인자와 대조할 때는 모든 공백을 제거한 문자열끼리 비교한다 ("중앙광장"으로 입력해도 "중앙 광장"에 매칭)

### 2.1 진입 시트 (시트명: 진입)

| 컬럼 | 내용 |
|---|---|
| A 현재 조사 가능 | 드롭다운. '가능'으로 표시된 경우 목록에 표시됨 |
| B 조사 오픈 일자 | 드롭다운. 장소 시트와 같은 선택지 |
| C 장소명 | 슬래시 사용 불가. 장소명 시트의 시트 이름과 정확히 일치 |
| D 진입 시 문구 | 장소에 처음 들어갈 때 출력됨 |

진입 가능 직군 컬럼은 없다. 장소 단위의 직군 제한은 존재하지 않으며,
진입 가능 여부는 그 장소 시트의 포인트 접근 가능성에서 파생된다 (아래 판정 규칙).
즉 "보안 경계는 군인만"은 진입 제한이 아니라, 보안 경계 시트의 모든 포인트가
군인 전용이라서 자연히 발생하는 결과다.

핵심 개념: 같은 장소명이 오픈 일자별로 여러 행 존재할 수 있다 (버전 시스템).
같은 장소라도 일차에 따라 진입 시 문구가 달라지기 때문이다.
예를 들어 '중앙 광장'은 1주-4일차 행과 2주-8일차 행이 따로 있고, 어느 시점이든
'가능' 상태인 행은 장소당 하나만 유지되는 것이 정상 상태다.

진입 판정 규칙 (캐릭터 X가 장소 P에 들어갈 수 있는 조건, 둘 다 충족):
1. 진입 시트에 P의 '현재 조사 가능 = 가능' 행이 존재한다 (빈칸은 불가능)
2. P의 장소 시트에 X가 조사 가능한 포인트가 1개 이상 있다
   (포인트가 조사 가능 = 해당 행이 '가능' 상태이고, X의 직군이 조사 가능 직군에 포함되거나 X의 예외 행이 존재)

부가 규칙:
- 진입 시 문구는 P의 '가능' 행에서 가져온다. '가능' 행이 둘 이상이면 그중 하나를 무작위로 선택한다 (문구 변주 지원)
- 조건 1이 거짓이거나 조건 2가 거짓이면, 진입 시도에 대해 동일한 실패 문구를 반환한다: "이곳에는 현재 조사할 수 있는 것이 없다." (장소가 닫힌 것인지, 자기 직군이 볼 게 없는 것인지 구분해 주지 않는다. 정보 비대칭 유지)
- 진입 시트에 아예 없는 장소명은 별도 문구: "그런 곳은 이 마을에 없다."
- [장소 목록] 출력 시 같은 장소명은 1회만 표시한다 (중복 제거)
- 같은 장소명의 '가능' 행들이 서로 다른 오픈 일자를 갖고 있으면(변주가 아닌 버전 중복) 정상 동작은 유지하되 관리자에게 경고를 보낸다. 버전 전환 누락 감지용 (장소 시트의 포인트에도 동일 적용)

### 2.2 장소명 시트 (장소마다 1개, 시트명 = 장소명)

| 컬럼 | 내용 |
|---|---|
| A 현재 조사 가능 | 드롭다운. '가능'으로 표시된 경우 목록에 표시됨. 빈칸은 불가능으로 취급 |
| B 조사 오픈 일자 | 드롭다운: 1주-4일차, 2주-8일차, 2주-11일차, 3주-16일차, 3주-18일차, 3주-20일차, 4주-23일차, 4주-26일차 |
| C 조사 가능 직군 | 다중 선택 칩 |
| D 조사 포인트 | 슬래시 사용 불가. 같은 포인트명이 여러 행 존재할 수 있음 (아래 버전·변주 규칙 참조) |
| E 조사 시 문구 | 조사 시 출력됨 |
| F 획득 아이템 | '상점' 워크시트에 있는 아이템명 1종. 쉼표 없음. 빈 값 가능 |
| G 개수 | 정수, ndm, ndm+k, ndm-k, -(ndm+3) 형식 |
| H 변동 스탯 | 드롭다운. '관리' 워크시트에 있는 스탯 (건강, 이성) |
| I 수치 | G와 같은 형식. 음수 허용 |
| J 재화 증감 | G와 같은 형식. 음수 허용 |

템플릿 시트("이 워크시트 복사 후 시트 이름을 장소명으로 변경")는 장소 시트 목록에서 제외할 것. 진입 시트의 장소명 컬럼을 장소 시트의 화이트리스트로 사용하면 안전하다.

포인트의 버전·변주 규칙 (진입 시트와 동일한 개념):
- 버전: 같은 포인트명이 다른 오픈 일자로 여러 행 존재할 수 있다. 예를 들어 '부검실'은 1주-4일차 문구(비어 있음)와 3주-16일차 문구(시신 안치)가 별도 행이다. 일차가 바뀌면 스케줄러가 이전 버전을 불가능으로, 새 버전을 가능으로 전환한다 (6.1 참조)
- 변주: 같은 포인트명의 '가능' 행이 동시에 둘 이상이면, 조사 시 그중 하나를 무작위로 선택해 그 행의 문구와 보상을 적용한다. 조사할 때마다 다른 묘사가 나오는 랜덤 변주 용도다
- 목록 출력 시 같은 포인트명은 1회만 표시한다 (중복 제거)
- 직군 판정: 목록 표시는 '가능' 행 중 하나라도 캐릭터가 접근 가능하면 표시. 조사 시 무작위 선택은 캐릭터가 접근 가능한 행들 중에서만 수행한다

아이템 개수 규칙:
- 획득 아이템이 있는데 개수가 빈칸이면 1로 취급한다
- 개수에 음수(예: -(1d2))가 오는 경우는 지원하지 않는다. 발견 시 해당 아이템 지급만 건너뛰고 관리자 경고

### 2.3 예외 시트 (시트명: 예외)

| 컬럼 | 내용 |
|---|---|
| A 캐릭터명 | 관리 시트 기준 이름. 슬래시 사용 불가 |
| B 장소명 | |
| C 포인트명 | |
| D 조사 시 문구 | 이 캐릭터가 이 포인트를 조사할 때 대신 나오는 특수 문구 |

예외 행의 의미 (중요):
1. 문구 대체: 해당 캐릭터가 해당 포인트를 조사하면 기본 문구 대신 D의 문구를 출력한다
2. 접근 부여: 해당 캐릭터는 그 포인트의 '조사 가능 직군'에 자기 직군이 없어도 조사할 수 있고, 목록에도 보인다. 의무 계열 캐릭터에게 연구소 진료 대장을 열어 주는 식의 용도
3. 예외는 문구와 접근만 바꾼다. 아이템, 스탯, 재화는 기본 행의 값을 그대로 따른다
4. '현재 조사 가능 = 불가능'인 포인트는 예외가 있어도 조사할 수 없다. 개방 여부가 항상 우선한다
5. 진입은 별도 처리가 필요 없다. 예외로 조사 가능한 포인트가 생기면 2.1의 진입 판정 조건 2가 자동으로 충족되어 그 장소에 들어갈 수 있게 된다

시트 작성 규칙 (봇이 강제하지 않는 운영 약속):
- 변주 세트(같은 이름, 같은 오픈 일자의 행들)는 아이템, 스탯, 재화 컬럼을 통일할 것. 변주 간 보상이 다르면 러너가 유리한 결과가 나올 때까지 반복 조사하는 복권이 된다
- 버전 전환이 있는 일차에는 예외 시트를 점검할 것. 예외 문구는 포인트명 기준이라 버전이 갈려도 계속 적용되므로, 구버전 상황을 전제한 예외 문구가 새 버전과 어긋날 수 있다

### 2.4 로그 시트 (시트명: 로그)

| 컬럼 | 내용 |
|---|---|
| A 일시 | MM.DD HH:MM (KST) |
| B 캐릭터명 | 관리 시트 기준 이름 |
| C 장소명 | |
| D 포인트명 | 진입 기록이면 빈 칸 |
| E 결과 | 아래 5.4 참조 |

봇은 이 시트에 추가(append)만 한다. 수정과 삭제는 하지 않는다.

### 2.5 참조하는 다른 시트

- 관리: 캐릭터명(마스토돈 계정 ↔ 캐릭터 매핑 포함으로 가정), 직군, 건강, 이성, 재화 잔액
- 상점: 아이템 목록. 획득 아이템 검증용
- 인벤토리(또는 관리 시트 내 소지품): 아이템 지급 기록처

이 시트들의 정확한 컬럼 구조는 구현 시작 전에 확인이 필요하다 (9장 오픈 이슈 참조). 계정 핸들 ↔ 캐릭터명 매핑이 없다면 관리 시트에 '계정' 컬럼 추가를 요청할 것.

## 3. 명령어 명세

명령어는 대괄호 안에 쓴다. 명령어 앞뒤의 일반 텍스트(연기 지문)는 무시한다.
하나의 툿에 명령어가 2개 이상이면 첫 번째만 처리하고 나머지는 무시한다.
파싱은 대괄호 안 문자열 기준. 슬래시로 명령과 인자를 구분한다. 인자의 앞뒤 공백은 제거(trim)한다.

### 3.1 [장소 목록]

2.1의 진입 판정(조건 1과 2)을 모든 장소에 대해 수행하고, 통과한 장소만 나열한다.
즉 진입 시트가 '가능'이더라도 캐릭터가 조사할 포인트가 하나도 없는 장소는 목록에서 빠진다.
예: 기술공이 조사할 포인트가 중앙 광장과 연구소에만 있다면, 기술공의 [장소 목록]에는 그 둘만 뜬다.
장소 수 × 포인트 수만큼의 판정이 필요하므로 시트 캐시를 활용해 계산할 것.

응답 템플릿:
```
@{계정}
현재 진입할 수 있는 장소는 다음과 같습니다.
- {장소명}
- {장소명}
[진입/장소명]으로 조사를 시작할 수 있습니다.
```

### 3.2 [진입/장소명]

판정 순서:
1. 장소명이 진입 시트에 존재하는가 → 없으면 실패 ("그런 곳은 이 마을에 없다.")
2. 2.1의 진입 판정 조건 1과 2를 모두 충족하는가 → 아니면 실패 ("이곳에는 현재 조사할 수 있는 것이 없다.")
3. 성공. 캐릭터의 현재 위치를 그 장소로 설정하고(세션 상태, 5.1 참조) 응답:
```
@{계정} {진입 시 문구} {포인트 목록 문장}
```
포인트 목록 문장은 봇이 동적으로 생성한다: "[{포인트1}], [{포인트2}], [{포인트3}]을(를) 조사할 수 있다."
포인트 목록에 포함되는 조건: 현재 조사 가능 = 가능, 그리고 (조사 가능 직군에 캐릭터 직군 포함 또는 예외 행 존재).
받침에 따른 을/를 처리는 마지막 포인트명의 종성 유무로 판단한다. 구현이 번거로우면 "을(를)"로 통일해도 된다.

### 3.3 [조사/포인트명]

판정 순서:
1. 캐릭터의 현재 위치가 설정되어 있는가 → 없으면 "먼저 [진입/장소명]으로 장소에 들어가야 한다." 실패
2. 현재 위치 장소 시트에 해당 포인트명의 행이 존재하는가 → 없으면 실패
3. 그 포인트명의 행 중 '현재 조사 가능 = 가능'이면서 캐릭터가 접근 가능한(직군 포함 또는 예외 행 존재) 행이 있는가 → 없으면 실패 (존재하지 않는 것처럼 응답. "그곳에서는 조사할 것이 없다.". 권한 없음을 티 내지 않는다. 정보 비대칭 유지가 목적)
4. 조건을 만족하는 행이 둘 이상이면 하나를 무작위 선택한다. 이후 문구와 보상은 선택된 행 기준
5. 일일 조사 횟수 확인 (5.2) → 초과면 실패
6. 재화 증감이 음수인 경우 잔액 확인 → 부족하면 실패 ("주머니 사정이 여의치 않다."), 아무것도 적용하지 않음
7. 전부 통과 시: 주사위 굴림 → 아이템, 스탯, 재화 적용 → 로그 기록 → 응답

응답 템플릿:
```
@{계정}
[{포인트명}]
{조사 시 문구 (예외 행이 있으면 예외 문구)}
➭ '{아이템명}' {n}개 획득
➭ {스탯} {+/-}{n}
➭ {n}달러 {획득/지불}
```
➭ 줄은 실제 발생한 변동만 출력한다. 변동이 없으면 문구만 보낸다.
출력하는 수치는 주사위를 굴린 확정값이다. 수식이 아니라.

### 3.4 공통 실패 응답

실패 응답도 세계관 톤을 유지한다. 시스템 용어를 노출하지 않는다.
- 없는 장소: "그런 곳은 이 마을에 없다."
- 진입 불가 (장소가 닫혀 있거나 조사 가능한 포인트가 없음): "이곳에는 현재 조사할 수 있는 것이 없다."
- 조사 불가 포인트: "그곳에서는 더 조사할 것이 없다."
- 횟수 초과: "오늘은 너무 많이 돌아다녔다. 내일 다시 살펴보는 게 좋겠다."
- 잔액 부족: "주머니 사정이 여의치 않다."
- 미진입 상태의 조사: "어디서 조사할지부터 정해야 한다. [진입/장소명]"
문구는 config로 분리해 운영진이 수정할 수 있게 한다.

## 4. 주사위 파서

개수, 수치, 재화 증감 컬럼의 공통 파서. 지원 형식과 기대 결과:

| 입력 | 해석 | 결과 범위 |
|---|---|---|
| 3 | 정수 | 3 |
| -2 | 음의 정수 | -2 |
| 1d2 | 1회 2면체 | 1~2 |
| 2d6 | 2회 6면체 합 | 2~12 |
| 1d4+2 | 굴림 후 가산 | 3~6 |
| 2d6-1 | 굴림 후 감산 | 1~11 |
| -(1d2) | 굴림 결과의 부호 반전 | -2~-1 |
| -(1d4+3) | 괄호 안 계산 후 부호 반전 | -7~-4 |

- 정규식 예시: `^-?\d+$` 또는 `^(-\()?(\d+)d(\d+)([+-]\d+)?(\))?$`. 여는 괄호가 있으면 닫는 괄호 필수
- 빈 값은 0으로 취급 (해당 보상 없음)
- 파싱 불가능한 값은 해당 보상만 건너뛰고 경고를 관리자 로그에 남긴다. 조사 자체는 진행한다

## 5. 상태와 규칙

### 5.1 현재 위치 (세션)

- 캐릭터별로 마지막으로 진입한 장소를 기억한다
- 저장 위치: 봇 프로세스 메모리 + 재시작 대비 영속화. 별도 저장소를 만들기보다 로그 시트에서 해당 캐릭터의 가장 최근 진입 기록을 복원하는 방식을 권장 (추가 인프라 불필요)
- 위치는 새로 진입할 때마다 덮어쓴다. 만료 시간은 두지 않되, 게임 일차가 바뀌면(5.3) 초기화한다

### 5.2 일일 조사 횟수 제한

- 캐릭터당 하루 N회. 기본값 3, config로 조절 가능
- 카운트 대상은 성공한 [조사]만. [진입]과 [장소 목록], 실패한 조사는 세지 않는다
- 판정은 로그 시트에서 해당 캐릭터의 당일(5.3의 게임 일차 기준) 조사 기록 수를 세어 수행한다
- 같은 포인트 재조사 제한은 없다. 같은 날에 같은 포인트를 다시 조사해도 되고, 보상도 다시 지급된다 (횟수 제한이 유일한 브레이크)

### 5.3 게임 일차 계산

- 1일차 = 2026년 7월 17일
- 일차 전환 시각: 매일 00:00 KST (즉 달력 날짜와 일치)
- 게임일차 = (오늘 날짜 - 2026-07-17) + 1
- 이 값은 조사 횟수 제한의 리셋과 스케줄러 계산에 쓰인다

### 5.4 로그 기록 형식

성공한 진입과 조사를 기록한다. 실패는 기록하지 않는다(단 관리자용 별도 로그 파일에는 남긴다).

- 진입: 일시 / 캐릭터명 / 장소명 / (포인트명 빈 칸) / "진입"
- 조사: 일시 / 캐릭터명 / 장소명 / 포인트명 / 변동 요약
- 변동 요약 예: "담배 1 획득", "이성 +2", "건강 -1", "재화 -5, 이성 +1", 변동 없으면 "조사"
- 일시 형식: MM.DD HH:MM (예: 07.20 21:14). 연도가 없으므로 파싱 시 2026년으로 가정한다. 이벤트가 7~8월 안에 끝나므로 연도 경계 문제는 없음

## 6. 스케줄러 (조사 자동 개방)

### 6.1 동작

- 조사 오픈 일자의 각 일차에 해당하는 날짜 21:00 KST에 실행된다
- 실행 순서 (한 번의 개방 작업 안에서):
  1. 장소 시트: 모든 장소 시트를 순회하며 '조사 오픈 일자'가 그 일차 값인 행의 '현재 조사 가능'을 '가능'으로 바꾼다. 이때 같은 시트 안에 같은 포인트명의 다른 오픈 일자 행이 '가능' 상태라면 '불가능'으로 바꾼다 (포인트 버전 전환. 예: 3주-16일차 개방 시 부검실의 3주-16일차 행을 켜고 1주-4일차 행을 끈다)
  2. 진입 시트 버전 전환: '조사 오픈 일자'가 그 일차 값인 행을 '가능'으로 바꾼다. 이때 같은 장소명의 다른 행(이전 버전)이 '가능' 상태라면 '불가능'으로 바꾼다. 예를 들어 2주-8일차 개방 시, 중앙 광장의 2주-8일차 행을 가능으로 켜고 1주-4일차 행을 불가능으로 끈다
- 버전 전환은 이번 일차에 새 행이 있는 이름(장소명, 포인트명)에만 적용한다. 새 행이 없는 이름의 기존 '가능' 행은 건드리지 않는다
- 주의: 같은 이름, 같은 오픈 일자의 행들(변주 세트)은 함께 켜지고 함께 유지된다. 버전 전환은 오픈 일자가 다른 행만 끈다

### 6.2 일차 ↔ 실행 일시 매핑 (하드코딩하지 말고 config로)

| 오픈 일자 값 | 실행 일시 (KST) |
|---|---|
| 1주-4일차 | 2026-07-20 21:00 |
| 2주-8일차 | 2026-07-24 21:00 |
| 2주-11일차 | 2026-07-27 21:00 |
| 3주-16일차 | 2026-08-01 21:00 |
| 3주-18일차 | 2026-08-03 21:00 |
| 3주-20일차 | 2026-08-05 21:00 |
| 4주-23일차 | 2026-08-08 21:00 |
| 4주-26일차 | 2026-08-11 21:00 |

### 6.3 필수 규칙

1. 단방향 원칙: 스케줄러가 무언가를 '불가능'으로 바꾸는 유일한 경우는 버전 전환(6.1)이며, 이는 이번 일차에 새 버전 행이 생긴 이름의 이전 버전 행에만 적용된다. 그 외에는 켜기만 한다
2. 운영 수동 조작 존중: 운영진이 아무 때나 특정 포인트나 진입 행을 수동으로 켜고 닫을 수 있다. 스케줄러가 이를 되돌리면 안 된다. 따라서 각 오픈 일자의 개방은 정확히 그 시각에 한 번만 실행하고, 재실행이나 주기적 동기화(예: 매시간 오픈 일자와 대조해 강제로 맞추는 방식)를 하지 않는다
3. 멱등성: 봇 재시작 등으로 같은 개방이 중복 실행되어도 결과가 같도록 한다 (이미 가능인 행은 건너뜀)
4. 놓친 실행 처리: 실행 시각에 봇이 죽어 있었던 경우를 대비해, 기동 시 "지나간 오픈 일시 중 아직 실행 기록이 없는 것"을 감지해 1회 보정 실행한다. 실행 기록은 로컬 파일이나 관리용 시트 셀에 남긴다. 단 이 보정도 운영진이 그 사이 수동으로 닫은 행을 되켤 위험이 있으므로, 보정 실행 시에는 관리자에게 알림을 보내고 확인 후 실행하는 옵션을 권장
5. 개방 완료 후 관리자 계정에 DM 알림: "{일차} 조사 {n}건 개방 완료"

## 7. 동시성과 안정성

- 스탯과 재화 갱신은 읽기-수정-쓰기 경합이 발생할 수 있다. 캐릭터 단위 락(프로세스 내 뮤텍스)으로 직렬화할 것. 봇 인스턴스는 1개만 띄우는 것을 전제한다
- 시트 쓰기 실패 시: 보상 적용 전 실패면 사용자에게 일시 오류 안내, 일부 적용 후 실패면 관리자 알림 필수 (수동 정산 필요 케이스)
- 응답 발송과 시트 기록의 순서: 시트 기록(스탯, 로그)을 먼저 완료한 뒤 답글을 보낸다. 답글 발송 실패는 재시도 1회 후 관리자 로그
- 마스토돈 스트리밍 연결은 끊김 감지 후 자동 재접속. 재접속 사이에 놓친 멘션은 notifications API로 보충 폴링
- 멘션 중복 처리 방지: 처리한 status id를 기억해 중복 응답을 막는다

## 8. 설정 파일 (config)

최소한 다음을 코드 밖으로 뺄 것:
- 스프레드시트 ID, 서비스 계정 키 경로
- 마스토돈 인스턴스 URL, 봇 계정 토큰, 관리자 계정
- 1일차 기준 날짜 (2026-07-17), 일차 전환 시각 (00:00), 오픈 시각 (21:00)
- 오픈 일자 목록 (6.2 표)
- 일일 조사 횟수 (기본 3)
- 오픈일 횟수 보정 옵션 (기본 꺼짐): 켜면 21:00 개방 시각에 그날의 조사 횟수를 리셋하거나 +1 부여. 스진(21시) 직후 신규 조사 러시를 허용할지에 대한 운영 선택지. 값은 off / reset / plus_one 세 가지
- 실패 응답 문구 세트 (3.4)
- 시트명 상수 (진입, 예외, 로그, 관리, 상점) 및 템플릿 시트명 (제외 대상)

## 9. 오픈 이슈 (구현 전 운영자 확인 필요)

1. 관리 시트의 정확한 컬럼 구조 (캐릭터명, 계정 핸들, 직군, 건강, 이성, 재화의 위치)
2. 마스토돈 계정 ↔ 캐릭터명 매핑 방법. 관리 시트에 계정 컬럼이 있는지
3. 아이템 지급의 기록처 (인벤토리 시트 유무와 구조)
4. 스탯 상한과 하한 처리. 100 초과 회복은 100으로 클램프하는지, 0 이하로 떨어지면 봇이 특수 동작(관리자 알림 등)을 하는지
5. 명령을 공개 툿으로 보낸 경우와 DM으로 보낸 경우 응답 공개 범위 정책 (조사 결과는 남이 보면 안 되는 정보일 수 있음. 전부 DM 응답으로 강제하는 것도 방법)
6. 진입 시 문구의 을/를 조사 처리 수준
7. 하루 조사 횟수 기본값 (2회인지 3회인지)

## 10. 수용 테스트 시나리오

구현 완료 판정 기준. 전부 통과해야 한다.

1. 개장 직후(1~3일차) [장소 목록] → 아무 장소도 나오지 않음 (진입 시트 전 행이 불가능 상태)
2. 7/20 21:00 → 장소 시트의 1주-4일차 포인트 35개와 진입 시트의 1주-4일차 행 9개가 가능으로 전환, 관리자 DM 수신
2-1. 진입 시트에 중앙 광장의 2주-8일차 행(다른 문구)을 미리 넣어 둔 상태에서 7/24 21:00 → 중앙 광장의 1주-4일차 행이 불가능, 2주-8일차 행이 가능으로 전환. [진입/중앙 광장] 시 새 문구 출력. 2주-8일차 행이 없는 장소(예: 보안 경계)는 1주-4일차 행이 가능인 채 유지
2-2. 중앙 광장 시트에 '급수대 줄' 1주-4일차 행을 문구만 다르게 2개 넣고 둘 다 가능 상태 → [조사/급수대 줄] 반복 시 두 문구가 무작위로 섞여 나옴. 목록에는 급수대 줄이 1회만 표시됨
2-3. 연구소 시트에 '부검실'의 3주-16일차 행(시신 문구)을 추가해 둔 상태에서 8/1 21:00 → 1주-4일차 부검실 행이 불가능, 3주-16일차 행이 가능으로 전환
3. 연구자 캐릭터 [진입/연구소] → 진입 문구 + 전압계, 분광 분석 기록, 방사선 측정기, 야금 실험대, 진료 대장, 부검실 목록
4. 기술공 캐릭터 [진입/연구소] → 진입 문구 + 야금 실험대만 목록에 표시
5. 가족 캐릭터 [진입/연구소] → "이곳에는 현재 조사할 수 있는 것이 없다." (연구소에 가족이 조사 가능한 포인트가 없으므로)
5-1. 가족 캐릭터 [장소 목록] → 연구소, 광산, 외곽 시험장, 보안 경계가 목록에서 빠짐 (가족 접근 포인트가 없는 장소들)
5-2. 진입 시트의 연구소 행을 수동으로 불가능 처리 → 연구자 캐릭터의 [진입/연구소]도 "이곳에는 현재 조사할 수 있는 것이 없다." (포인트가 열려 있어도 진입 행이 닫히면 차단)
6. 예외 시트에 (간호사A, 연구소, 진료 대장, 특수문구) 추가 후 가족 직군 간호사A [진입/연구소] → 성공, 목록에 진료 대장 표시. [조사/진료 대장] → 특수문구 출력
7. [조사/방사선 측정기] → 문구 + 건강 -1 또는 -2, 관리 시트 반영, 로그 1행 추가
8. 재화 3달러인 캐릭터 [조사/바 카운터] → 잔액 부족 실패, 이성과 재화 변동 없음
9. 같은 캐릭터가 하루 4번째 [조사] → 횟수 초과 실패
10. 운영자가 수위계를 수동으로 불가능 처리 → 목록에서 사라지고 조사 실패. 이후 어떤 자동 동작도 이를 가능으로 되돌리지 않음
11. 봇 재시작 후 [조사/게시판] → 현재 위치가 로그에서 복원되어 정상 동작
12. 대괄호 없는 일반 멘션 → 무응답 또는 안내 1회 (config로 선택)
