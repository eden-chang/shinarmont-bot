## 2. 가이드와 기존 기획이 충돌한 지점

가이드가 우선("아래 명세를 우선하되")이므로 기본적으로 가이드를 따랐다. 예외는 아래 두 건.

### 2.1 조사 횟수 판정: 로그 시트 + 관리 시트 미러 (둘 다)

- **판정 기준(single source of truth)은 `로그` 시트**다. 가이드 §5.2 그대로 당일 조사 기록 수를 센다.
- 동시에 `관리` 시트 `오늘조사` 컬럼에도 값을 **미러링**한다(`INVESTIGATION_MIRROR_COUNTER`). 기존 기획의 GM 트래킹 용도를 유지하기 위함.
- 미러 값은 **로그에서 센 값을 그대로 쓴다.** 그래서 카운터가 어긋나 있어도 조사할 때마다 자동 교정된다.
- `daily_counter.check_and_inc_sheet`를 쓰지 않는다. 그 함수는 자체적으로 사용자 락을 잡는데 조사 명령은 이미 같은 락 안이고 `threading.Lock`은 재진입이 불가능하다(락 대기 → 10초 후 실패). 대신 보상 배치에 카운터 갱신을 함께 실어 API 호출도 아꼈다.
- 스케줄러의 00:00 `reset_sheet_counters`는 그대로 둔다(미러 값 초기화). 판정은 로그 기준이라 리셋 누락이 있어도 게임 규칙은 깨지지 않는다.

### 2.2 이성 왜곡(distortion) 적용

가이드에는 언급이 없으나 기존 기획에 있어 **적용**한다.

- `utils/distortion.apply`를 **조사 시 문구(서술)에만** 적용한다. 이성 ≤ 40 마스킹, ≤ 20 오정보.
- `➭` 변동 줄은 **왜곡하지 않는다.** 시트에 실제로 반영된 값이라 왜곡하면 러너가 자기 스탯을 오해한다.
- 오정보 치환 후보 풀은 **현재 장소를 제외한 다른 장소명**이다(같은 세계관 어휘로 바꿔야 그럴듯한 거짓이 된다).
- `INVESTIGATION_DISTORTION_ENABLED=False`로 끌 수 있다.

## 3. 재량으로 결정한 세부 구현

### 3.1 시트 장애를 '닫힌 장소'로 오해시키지 않기 (중요)

`SheetsManager.get_worksheet_data`는 **실패해도 예외를 던지지 않고 `[]`를 반환**한다(`safe_execute(fallback_return=[])`). 즉 *시트 없음* / *API 장애* / *진짜 빈 시트*가 전부 `[]`로 뭉개진다.

그대로 두면 Sheets 장애 중에 러너에게 **"이곳에는 현재 조사할 수 있는 것이 없다."**(= 장소가 닫혔다)라고 거짓말을 하게 된다. 그래서:

- 비어 있으면 안 되는 시트(`진입`, 장소 시트)는 `allow_empty=False`로 읽어 **빈 결과를 장애로 취급**하고 `InvestigationDataError` → 일시 오류 문구로 응답한다.
- 빈 결과가 정상인 시트(`예외`, `로그`)는 그대로 허용한다.
- `[장소 목록]`에서 특정 장소 시트만 읽히지 않으면 그 장소만 건너뛰고 관리자에게 경고한다(전체 목록은 살린다).

### 3.2 이름 비교

모든 이름 비교(장소명·포인트명·캐릭터명·직군)는 **공백을 전부 제거**하고 수행한다. 실제 조사 시트에 `외곽  시험장`(공백 2개)처럼 표기된 시트가 있어 필수다. 출력은 시트 표기를 그대로 쓴다.

### 3.3 주사위를 잔액 검사보다 먼저 굴린다

가이드 §3.3은 잔액 확인(6) → 굴림(7) 순서지만, 재화 증감이 `-(1d4+3)` 같은 수식일 수 있어 **굴려야 금액을 알 수 있다.** 굴림은 시트를 건드리지 않으므로 잔액 부족으로 중단해도 아무 상태도 바뀌지 않는다(가이드의 "아무것도 적용하지 않음" 보장은 유지).

### 3.4 상점에 없는 아이템

관리자에게 경고하되 **지급은 한다.** 건너뛰면 러너가 보상을 조용히 잃지만, 지급해 두면 GM이 사후 정정할 수 있다.

### 3.5 예외 행의 문구가 비어 있을 때

**접근 권한만 부여하고 기본 문구로 폴백**한다. 예외 시트를 '접근 부여' 용도로만 쓰고 싶은 경우를 지원한다.

### 3.6 오픈일 조사 횟수 보정 (`INVESTIGATION_OPEN_ADJUST`)

횟수 판정이 로그 집계라 '카운터 리셋'이라는 개념이 없다. 대신:

- `reset` → 개방 시각(21:00) **이후의 조사만 센다** (사실상 그날 리셋)
- `plus_one` → 그날 한도를 1 늘린다
- 둘 다 **개방 시각이 지난 개방일에만** 적용된다. 기본 `off`.

### 3.7 실패 응답의 반환 형태

세계관 톤의 거절(장소 없음/조사할 것 없음/횟수 초과 등)은 **정상적인 게임 진행**이므로 `CommandResponse.create_success`로 돌려준다. `create_error`는 시트 장애 같은 진짜 오류에만 쓴다. 스트림 핸들러는 둘 다 답글로 보내지만 오류는 ❌로 로깅되고 실패 통계에 잡힌다.

### 3.8 현재 위치 만료

항목마다 진입 **날짜**를 함께 저장하고, 날짜가 다르면 없는 것으로 취급한다. 스케줄러의 일괄 초기화에 의존하지 않으므로 자정을 넘겨도 항상 정확하다(가이드 §5.1 "게임 일차가 바뀌면 초기화").

### 3.9 관리자 알림

`utils/investigation_notify.py`. DM 발송은 best-effort이며 실패해도 명령 처리를 막지 않고 항상 로컬 로그에 남는다. 버전 중복처럼 매 명령마다 재발견되는 경고는 **프로세스당 1회만** 발송한다(`notify_admin_once`).

### 3.10 놓친 개방 보정

기본값은 **관리자에게 알리기만 하고 실행하지 않는다**(`INVESTIGATION_MISSED_OPEN_CONFIRM=True`). 보정 실행이 운영진이 수동으로 닫아 둔 행을 되켤 수 있기 때문(가이드 §6.3-2 운영 수동 조작 존중). 확인 후 `[조사 개방/일차]`(관리자 전용)로 수동 실행한다.

## 4. 발견한 버그 (수정함)

`int(getattr(config, KEY, default) or default)` 관용구는 **0이 falsy**라서 `0 or 21 == 21`이 된다.
개방 시각 `0`시나 일일 조사 횟수 `0`(조사 비활성화) 같은 유효한 설정이 조용히 무시됐다.
→ `investigation_sheet.config_int()`로 교체. `None`/빈 문자열만 기본값으로 폴백한다.

## 5. ⚠️ 시트 내용과 가이드 수용 테스트의 불일치 (GM 확인 필요)

실제 조사 시트(`INVESTIGATION_SHEET_ID`)를 읽어 가이드 §10 수용 테스트를 대조한 결과다.
**코드가 아니라 시트 내용 쪽 문제**로 보인다.

| 수용 테스트 | 기대 | 실제 시트 | 판정 |
|---|---|---|---|
| §10-1 개장 직후 [장소 목록] | 아무 장소도 안 나옴 | 진입 시트 전 행이 빈칸(=불가능) | ✅ 일치 |
| §10-2 1주-4일차 개방 | 포인트 **35**개 / 진입 **9**개 | 포인트 **36**개 / 진입 9개 | ⚠️ **포인트 1개 초과** |
| §10-3 연구자 [진입/연구소] | 전압계·분광 분석 기록·방사선 측정기·야금 실험대·진료 대장·부검실 (6) | 정확히 그 6개 | ✅ 일치 |
| §10-4 기술공 [진입/연구소] | **야금 실험대만** 표시 | 야금 실험대 직군 = `연구자`뿐 → **기술공은 연구소 진입 자체가 불가** | ⚠️ **불일치** |
| §10-5 가족 [진입/연구소] | "조사할 수 있는 것이 없다." | 가족 접근 포인트 없음 | ✅ 일치 |
| §10-5-1 가족 [장소 목록] | 연구소·광산·외곽 시험장·보안 경계 빠짐 | 정확히 그 4곳이 빠짐 | ✅ 일치 |

### 조치가 필요한 것

1. **야금 실험대의 `조사 가능 직군`에 `기술공` 추가** — §10-4를 만족시키려면 필요하다. 현재는 `연구자`만 있어 기술공이 연구소에 아예 들어갈 수 없다.
2. **1주-4일차 포인트 36 vs 35** — 가이드 작성 이후 포인트가 하나 늘었거나 가이드의 숫자가 근사치일 수 있다. 어느 쪽이 맞는지 GM 확인 필요. (현재 1주-4일차 분포: 중앙 광장 4 / 연구소 6 / 광산 3 / 옛 채굴촌 4 / 외곽 시험장 3 / 행정 구역 5 / 주거 구역 4 / 생활 시설 4 / 보안 경계 3)

### 그 밖에 확인한 것

- `예외` 시트는 현재 **비어 있다**(0행). §10-6 테스트를 하려면 GM이 행을 넣어야 한다.
- §10-2-2(급수대 줄 변주), §10-2-3(부검실 3주-16일차 버전) 행도 아직 없다. 코드는 지원하며 단위 테스트로 검증되어 있다.
- `방사선 측정기`는 `건강 = -2` 고정이다. 가이드 §10-7은 "건강 -1 또는 -2"라 주사위(`-(1d2)`)를 전제한 듯하나, 고정값도 정상 동작한다.
- 버전 중복(같은 이름의 '가능' 행이 서로 다른 오픈 일자)은 **현재 없다**.

## 6. 구현 구조

| 파일 | 역할 |
|------|------|
| `utils/investigation_sheet.py` | 진입/장소/예외 시트 읽기 + 판정 코어(이름 정규화·직군·예외·변주·버전 중복) |

| `utils/investigation_open.py` | 조사 자동 개방(버전 전환·멱등·실행 기록·놓친 실행) |

### 알아둘 한계

- 개방 실행 기록(`state/investigation_opens.json`)은 프로세스 내 락으로만 보호된다. 멀티 슬롯에서 두 프로세스가 동시에 개방을 쓰면 경합할 수 있다. 실제로는 `SCHEDULER_OWNER` 슬롯 1개만 자동 개방하므로 문제되지 않는다.
- 조사 시트 캐시 TTL(60초) 동안 `[장소 목록]`은 최대 60초 낡은 개방 상태를 보여 줄 수 있다. `[진입]`·`[조사]`는 미캐시로 재검증하므로 실제 판정은 항상 최신이다.
